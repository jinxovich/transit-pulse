# Политика алертов: реплей на честных прогнозах

Реплей логики `IncidentBook` (`scripts/alert_replay.py`) на дампе потокового прогона за 06.01.2026 (`data/eval/stream_dump.pkl`, 13 ТС, 215 ТС·ч в режиме готовности). Прогнозы — **честные** ответы фолд-моделей (`h_*`), факт `test/schedule.csv` используется только для закрытия инцидентов и оценки.

Метрики: точность — доля инцидентов с фактической задержкой цели > 120 c; полнота по рейсам — доля опоздавших рейсов (≥ 1 визит с фактом > 120 c среди визитов, побывавших в окне прогноза; всего 96) с инцидентом на этом рейсе; полнота по визитам — то же по визитам (1281); F1 — по точности и полноте по рейсам. Серия N — сколько проходов (сим-минут) подряд визит окна удовлетворял условию.

## Проверка реплея

Текущая политика на прогнозах **финальной** модели: реплей — инцидентов 245, точность 53.5%; онлайн-прогон — инцидентов 241, точность 51.9%. Общих целей 220, из них открыты в ту же сим-минуту 215. Расхождение — из-за закрытия: онлайн — по виртуальному прибытию из GPS-трека, в реплее — по факту расписания.

## Вывод

Серия из 2 проходов и чуть более строгий порог отсекают «мигающие» красные прогнозы: алертов на ТС·ч 1.24 → 0.79, точность 41.0% → 51.5% при полноте по рейсам 90.6% → 80.2%; упреждение по-прежнему 100% ≥ 10 мин. Выборка мала (один день, 13 ТС) и политика подобрана на ней же — разница между верхними строками топа в пределах шума, поэтому пороги вынесены в env (`ALERT_*`).
